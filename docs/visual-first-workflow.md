# 先画面，后配音

自由画面源码支持两种顺序：

1. 配音优先：口播稿 -> 配音及实测字幕 -> 生成定制视觉 -> 审批预览 -> 验收导出。
2. 画面优先：口播稿 -> 生成视觉草稿 -> 审批无声预览 -> 配音及实测字幕 -> 按实测配音对齐 -> 审批新源码和预览 -> 验收导出。

草稿生成仍会调用最多两次模型，但不需要先付费配音。草稿时长按约280字/分钟估算，仅用于画面评估；草稿预览使用本地静音文件，字幕也是估时。服务端禁止草稿验收及整课导出。实验性宿主模式仍需配音优先。

“按实测配音对齐”不调用模型或TTS。宿主依据原口播文字与实测字幕的字符位置生成单调帧映射，保留原绘图与动作源码；字幕跨越草稿节拍时只在共同文本边界合并设计节拍，不拆造实测字幕。生成新哈希，保留旧稿，不自动执行或继承旧验收。重新审批、几何检查和人工预览仍是正式交付门槛。

草稿只依赖口播与设计输入，配音更新不使其失效；修改口播会失效。已对齐画面继续绑定实际音频、字幕及章节版本，配音变化会失效。

限制：需为接收frame参数的具名默认函数，直接使用Remotion时钟hook、无法映射的字幕或超出设计结构限制时会明确失败，不自动调用模型修复。时间压缩可能改变动作节奏，必须重新看预览；这不等于自动画质验收。

开发验证不调用模型/TTS，不修改已有8章课程。覆盖估时输入、草稿不可验收/导出、配音后保留草稿、免费对齐零请求、新哈希审批、章节改稿失效及完整任务生命周期。

# 标签布局建议工作流

1. 当前有效的source生成任务在设计阶段失败且记录一次请求，可POST /{job}/propose-layout，body仅{confirmed:true}。
2. 零模型的propose-layout队列任务验证原失败响应与冻结设计一致，复用既有独立标签纵向建议算法。它不移动实体、不改口播/时间轴、不增加遮挡豁免。新旧坐标、未解决告警及设计在网页以文本展示，不执行场景。
3. 建议独立保存layout-proposal.json、design.json、result.json。原失败任务和文件不改，提案未采用，不可预览/验收/导出。即使无解也保留真实layout_preflight=failed，供用户看清原因。
4. 只有预检通过且moves非空时可POST /{proposal}/apply-layout，明确确认max_requests=1、design_sha256和layout_sha256。采纳创建新的repair任务，仅请求源码，不重做设计/配音；失败不重试。
5. 代码请求前重新验证原响应、重算建议、核对审批哈希/设计/课程快照和真实音频checksum。Node保留layout-input.json；新源码经原护栏/类型检查，执行仍须单独批准精确源码哈希。

数据库v5迁移仅增加propose-layout任务kind，保留历史记录。任务属于workflow队列、默认60秒上限、不继承模型密钥。页面不接受任意路径或上传未绑定设计；未知/截断/非法设计响应无法通过原稿绑定检查。

本步骤不处理实体级布局求解，不证明移动后的字体、路线、遮挡或连续动作正确，也不代表Agent自动画质验收。继续按统一任务清单的动作反馈、单章预览与跨题材验证推进。

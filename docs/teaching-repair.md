# 教学计划自动修复：离线基础

本页主要记录A/B阶段。后续C1已加入DOM诊断回流及显式免费恢复入口，布局/运动编译器当前为v3；详见`docs/teaching-render-recovery.md`。T6整体仍未验收。

## 免费修复

布局器`teaching-layout-engine:2`保留主结构的位置，辅助对象先尝试原槽位，再尝试其他预设槽位及24个宿主格点。最多4个辅助对象、累计20000次候选搜索；失败明确拒绝，不删对象、不缩放、不改文案，12px对象间距保持不变。搜索带回溯，不把一次贪心失败当成无解。

所有被采用的移位记录在`adjustments`，运动编译器v2透传`layoutAdjustments`，参与原有哈希绑定。后续完整运动编译仍会执行接收容量、真实路线、逐帧与扫掠检查，排版通过不豁免运动冲突。已存在的字号/换行与全尺寸避障求解继续复用。

这不是通用装箱求解器；超出候选集会明确失败。当前不自动移动主机构，也没有对实际DOM失败后重排整场景的闭环。

## 数据修订边界

`prepareTeachingCompilation`仅接受原严格协议可解析的计划：

- `compiled`：数值编译成功，仍`accepted:false`，不是MP4成功。
- `revision-required`：保留诊断stage/code/detail与原计划，生成`teaching-plan-revision:1`请求数据，绑定输入、原计划及请求哈希。
- `unsupported`：明确的结构/对象上限、固定画布、宿主时间不足或固定运输载荷文字容量不够，不生成无意义的模型重试请求。

协议或宿主上下文非法仍由原解析器拒绝；未识别的异常原样抛出，不伪装成可修内容问题。当前没有接入模型供应商、队列或预算扣减。

`validateTeachingRevision`必须接收请求之外、由宿主保存的可信`expectedRequestSha256`，然后在当前编译器重建原始失败并校验完整请求，拒绝篡改、替换原计划后重算哈希或输入变化。不得从不可信请求中复制同名哈希充作可信值；根任务持久化与派发入口留待T7/T8。修订只可改变组件引用及其初始状态；结构、全部对象ID/含义/完整标签/归属、关系和每个cue的有序动作必须保留。修订协议通过后仍必须重新数值编译、冻结、DOM检查与渲染，不能直接登记成功。

`buildTeachingRevisionPrompt`复用原教学协议，只附加经过绑定检查的诊断及修订约束。仅准备文本，不调用模型，也不允许隐式回退到自由源码。

## 当前范围

本次8项离线测试覆盖辅助对象移位、四种辅助对象数量、六类编译、容量失败绑定、篡改/替换基准/删文字/删动作拒绝、不支持能力与时间、非法协议、有效修订仍未解容量时不得成功，以及仅更换兼容组件后完整编译通过。后者是程序测试数据，不是模型自动修复成功案例。

T6仍未整体完成：实际DOM失败诊断接回、其他主结构布局变体、单次模型修订派发与恢复需继续实现，并依赖T7/T8。未调用模型/TTS，未重新渲染视频，未修改工作台或默认模式。

旧T5预览为原冻结运行时的历史证据。布局/编译器v2改变运行时绑定，旧产物不能在新运行时静默重放；必须显式重建新的冻结产物，不能沿用旧检查结果。

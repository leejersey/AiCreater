# 定制视觉工作台

主入口 `/courses/{id}` 使用定制视觉工作流；旧模板编辑器只在 `/courses/{id}/legacy` 显式打开。现有课程和口播保留，不会自动重建或付费生成。

## 生产链路

1. 免费整理空项目的口播章节，或复用已有章节。
2. 核对口播与音色，明确确认配音费用。使用真实音频及实测字幕，不按字数估算动画时间。已有配音但待对齐的章节可单独本地对齐。
3. 选择生成方式，再明确确认最多两次模型请求：视觉设计一次，源码或运动绘图数据一次。“宿主运动（实验）”由宿主将数据装配为源码；默认“源码生成（兼容）”不变。失败不重试，也不在两种模式间回退。失败候选保留；有完整候选时可明确确认单次修复。
4. 审核设计、源码和精确 SHA-256，再单独批准本地执行。生成源码只作为转义文本显示，不在登录网页执行。
5. 本地生成首、中、末等审查帧及几何报告；通过后生成带原配音和字幕的 MP4。几何检查不是审美验收，仍需人工检查与确认。
6. 全部当前章节验收后，冻结源码、设计、音频、字幕，统一渲染整课 MP4 与 SRT。

本地渲染不是安全沙箱：只批准已审阅且信任的源码。渲染进程不继承模型、配音、数据库或对象存储密钥，但仍可访问当前用户的本机资源。此版本只适用于可信的本地开发，不适合执行互不信任用户提交的代码。

## 后端边界

- 新任务保存在 PostgreSQL `visual_jobs`，与旧模板 `jobs` 分开，复用 `workflow`、`render` 两条 Celery 队列。
- 每个接口都有项目身份鉴权，任务也必须属于该项目。接口不接受文件路径或执行命令。
- 每次只认一个带令牌的执行尝试；取消、超时、失联不会自动再次调用供应商。
- 同一输入的活动任务重复提交会复用原任务，不额外派发付费请求。
- 源码批准绑定精确源码与 brief 的哈希；验收同时绑定设计及媒体指纹。口播、时长、字幕或音频变更后须重新生成和审核。
- `output/visual-workbench/{任务 UUID}/` 保存不可覆盖的产物与私有供应商记录；下载仅开放校验过哈希的源码文本、设计 JSON、审查 PNG、MP4、SRT。
- 模型请求前落盘请求计数；不把供应商原始响应、密钥或绝对路径返回网页。

当前单章支持实测 1–120 秒，最多 20 章。超限或缺失字幕时明确拒绝，不拉伸音频或编造时长。

## 数据式可选模式

`POST /generate` 可携带 `generation_mode:"source"|"host-motion"|"host-intent"`，缺省source。
服务端严格拒绝其他值，将host-motion冻结进任务输入并参与活动任务去重。
生成任务的设计修订、单次数据修订均继承父稿模式，不能通过网页当前选择或请求字段改写。
队列传递模式给Node；host-motion接受motion-assembly:2。host-intent的新动作请求使用object-motion-data:1，将同一对象的动作与artwork放在一个记录中，由宿主补brief/时长并拆出意图和绘图层；历史motion-intent-assembly:1仍可读取，不是新请求的降级输出。后者继续冻结原始版本化数据、编译装配及各自哈希，发布字段不变。

新host-intent任务的设计阶段使用visual-design-content:1：模型只返回视觉字段及宿主输入摘要，不重复brief/cues。宿主从私有design-input.json还原现有VisualDesign，继续执行完整状态与布局校验，缺少overlaps仍拒绝。source/host-motion保持原设计协议；历史完整设计响应仍可恢复。新协议不增加请求、自动重试或执行权限，真实供应商接受情况另行验证。
发布时拒绝模式降级或缺少装配哈希，预览前再次核对数据库中的装配元数据。
模式和装配哈希可在网页源码审核区查看。底层数据、供应商记录及文件路径不公开。
动作意图模式另显示intent SHA；成功结果须具备该模式、装配SHA及意图SHA。所有模式中出现的哈希字段均检查类型/格式，避免坏元数据使列表无法刷新。修复启动前磁盘模式须与数据库冻结模式一致，旧source仅在没有冻结运动数据时兼容缺失marker；预览访问音频前也核对数据库与磁盘意图/装配元数据。
网页新增“动作意图（实验）”，付费生成最多2次、数据修订最多1次；取消确认不提交，预览审批捕获的具体源码SHA随请求固定，后续版本变化须重新确认。父稿模式不能被当前选择器覆盖。

正式工作台已完成一次设计及数据两阶段真实请求；设计预检通过，但数据因帧边界、对象身份及层映射问题未通过，尚无自动画质验收。
数据生成和修订的输出Schema绑定冻结设计：每个对象ID必须恰好对应一条轨道和一层绘图，禁止另起t-/l-别名；装饰放在所属层内部。父级、审计层及跟随对象引用也使用该ID集合。
关键帧范围是0..durationInFrames-1；附件和跟随窗口的endFrame是排他边界，可等于durationInFrames。现有本地语义检查仍保留，不自动截短坏数据或重写ID。
仅brief调用的底层Schema保持兼容；上述设计绑定由正式工作台在设计通过后传入。最近一次真实数据请求已通过完整Schema，但在第430帧的附件交接连续性检查失败；不能据单次结构正确宣称长期稳定、语义正确或自动画质达标。
轨道字段只位于plan.tracks[]：id、keys，以及可选parentId或attachments。绘图层layers[]只含id与artwork；未使用的运动字段必须省略，不写null或空attachments。提示与Schema描述共享这一归属，附有一个对象的结构片段示例，不是完整响应或视觉模板。额外字段仍拒绝，不自动删除、迁移或改变其语义。
本地执行仍需具体源码哈希审批；几何failed仍不能正式验收或导出。

### 失败运动数据的设计复用

host-motion可通过现有repair入口复用冻结设计，仍最多1次数据请求。仅在旧目录没有artifact/result、模式为host-motion、failure与请求计数均为2时允许；设计须与完整stop的provider-1原始设计响应canonical哈希相同，并重新通过布局检查。坏运动JSON不作为有效装配使用，也不自动修补；反馈仍传入新数据请求。

已有源码/发布记录的完整性错误不能降级为此恢复路径。设计阶段失败、缺失/篡改设计、计数不符及软链拒绝，不自动借用别的任务设计。失败的单次修复不因此获得无限重试能力。新源码仍需具体哈希审批及视觉/几何验收。

## 布局预检

设计阶段失败且实际记录一次请求的任务，可显式调用`POST /{job_id}/revise-design`，提交`confirmed:true,max_requests:2,feedback`。它创建新的generate任务，记录design_revision_of关联，不重排旧任务。工作台按钮为“修订设计并生成源码”；源码阶段失败仍走原来的单次repair。

源码响应完整但在保存artifact之前被拒绝时，repair可从私有保留响应读取候选：仅限失败记录与请求计数一致、无已发布result、完整stop响应、有效冻结设计，且候选重新通过当前源码护栏和brief绑定。截断、软链、危险源码或计数不符均在新模型派发前拒绝。只读旧目录，不把失败任务改为成功；修订仍最多一次代码请求，不重做设计/配音，新源码仍需哈希审批。此恢复路径不适用于仍被源码护栏拒绝的候选。

执行器只读取所属项目、当前素材快照匹配的父任务私有原稿及错误信息。完整原稿必须满足新Schema形状（允许存在待修复的状态引用或布局问题）；截断、缺失、软链或不匹配在派发前停止。修订请求复用原稿并携带用户反馈和机器错误，通过引用/连续性/布局预检后才请求代码。最多2次，不自动重试或降级；原始文件不改写，新源码仍须具体哈希审批、实渲染和人工验收。

新设计阶段使用`design-schema.ts`构建的JSON Schema，同时放入提示和Responses接口的`text.format`。不再用省略关键字段的伪JSON形状作为输出模板。新输出的每个对象（含标签、路径）都必须声明1–8个状态，每项变化必须同时包含描述from/to与引用fromState/toState；静态对象可只有shown状态。只有parentId可缺省，也可显式为null表示无父级；解析后null规范化为字段缺省。字符串父级仍须存在且满足归属约束，空字符串和其它类型不转换。brief和实测cues必须原样返回。

设计、源码和数据式生成使用Responses结构化输出，各自使用对应Schema；本地AJV再次校验形状，随后原有解析器验证引用/连续性，布局预检通过后才发第二阶段请求。400、不完整输出、拒绝、工具调用或Schema不符均停止，不自动降级、修复或重试；原始文本仍在失败前私有保留，不输出密钥。新的数据式递归Schema仍需单独授权的真实测试，不能据离线mock宣称线上已通过。[接口说明](https://api-docs.deepseek.com/api/create-response/)

未来生成任务的教学节拍优先在实测字幕的句末结束，或在“首先、然后、接着、随后、最后、第X步”开头的字幕之前结束上一节拍。长句无上述边界时保留60字符回退；不在一条实测字幕内部估算时间，不改变配音、字幕及停顿。超过30个节拍仍要求拆章，不静默合并回去。它是标点/提示词启发式，不是完整语义理解。历史任务的冻结节拍不迁移。

对象空、满、组装后的形态应复用同一ID，写入`beats.changes`；临时运输组只在源码中提供共同变换，不成为另一份可见实体。设计与代码提示都要求保留身份、避免重复套筒或载荷。当前是生成约束，不是自动的实体同一性证明。

对象可声明`states:[{id,appearance}]`（1–8项，ID在该对象内唯一）。声明后，该对象每项变化都必须携带`fromState`、`toState`，引用必须存在；后续变化的`fromState`必须接上前一次`toState`，包括跨节拍和间隔停顿。只移动不变形时两者相同。状态参与设计哈希；旧文本变化仍可读取，不补写状态字段。该合同能验证显式状态链，不能通过自然语言证明不同对象名实际上属于同一实体，也不保证生成源码遵守。

独立文字、步骤编号和状态标记使用`kind:"label"`，它们与非路径对象的占位只要有正面积交叠即报`label-overlap`，不受实体12%阈值或`overlaps`声明豁免。标签不能有实体父级，也不能充当实体父级；字幕安全区不变。嵌入主体内部的固定文字可保留在主体`appearance`，但仍需实渲染检查。历史未分类对象不猜测其标签身份。

设计最多20个对象（独立标签、路径和部件均计数），提示与解析共用对象数量常量。普通固定细节可写入主体外观，不必每项成为独立对象。超限不裁剪、不自动重试，私有运行记录会报告字段、允许范围与实际数量；工作台继续显示固定安全错误消息。

新设计在代码请求之前检查对象占位。两个对象的交叠宽高均超过4px，且交叠面积达到较小对象的12%时，需要设计用`overlaps:[{a,b,reason}]`明确说明具体物理装配或遮挡关系，否则停止。对象底边不得进入y=980以下字幕区。原始设计和失败记录保留；失败仅消耗已派发的设计请求，不自动重做设计或请求代码。旧设计仍能加载、核对原哈希和渲染，但重新生成代码时可能需要先修正占位。

设计对象支持`kind:"solid"|"path"`，新设计提示要求明确分类。仅细线连接器和运动路线是`path`；纸张、容器、机器、标签及移动载荷即使只有轮廓也属于`solid`。路径的矩形范围不再参与实体两两碰撞判断，但仍检查字幕区；实际路径笔画与标签关系交给渲染检查。缺少分类的旧对象仍按实体检查，不通过名称猜测类型，也不补写字段，保持旧哈希不变。分类本身依赖模型正确描述，不是安全证明或视觉通过条件。

永久部件可声明可选的`parentId`，例如柜体开口所属柜体；直属父子对不需重复填写`overlaps`。父对象必须存在且不是路径，禁止自身归属和归属环；不推断旧文本的隐含关系。这个关系只豁免直属父子占位，不豁免同级部件、其它祖先、字幕区或渲染检查。临时插入的纸张、运输载荷不属于永久部件，应使用节拍和有理由的`overlaps`。所有设计坐标仍为画布绝对坐标，代码嵌套绘制时须减去父级原点，并让固定部件随主体移动；部件前后层次由`composition`明确。新增关系参与设计哈希，旧对象不补字段，旧哈希保持不变。

`overlaps`也可明确声明不同时出现的互斥阶段，避免禁止合理的同位置状态转变。声明不是审美通过，也不能豁免实际渲染的标签、路径和安全区检查。运动生成提示进一步要求：复合载荷共享父级变换、交接时用确定性帧数学计算世界坐标、每个阶段边界前后连续、外层路径锚点与内层图形居中偏移分开。当前这部分是生成约束，尚不是完整的运动语义自动证明；仍须审阅源码、实渲染和人工验收。

## 验证

### 独立几何诊断复核

`reviewGeometryDiagnostics`可在离线审阅中对指定源码哈希、精确告警三元组（kind/target/detail）和帧区间添加containment/occlusion说明。它不修改`analyzeGeometry`，不重新执行源码，不覆盖原始报告，不授予预览验收或整课导出资格。返回值固定为`diagnostic-only`及`accepted:false`；未匹配告警明确保留为unclassified。只有label-obstacle可附加此类关系说明，越界、路径偏移、其他标签或提前遮挡不能套用；重叠规则拒绝歧义。

RAG v4示例规则位于`examples/custom-scenes/reviewed-rag/geometry-review-policy.json`；输出复核另存`diagnostic-review.json`，记录原报告哈希及证据截图哈希。它是人工提供的预期关系分类，不是自动证明文字像素可见，也不解决未标注运动锚点的覆盖缺口。当前工作台验收门槛保持原样。

### 用户认可的视觉参考

工作台和独立visual-agent CLI共用`readReviewedCodingReference`，将钱包构造示例及用户认可的人工修订RAG v4作为文本参考，不导入执行示例模块。RAG参考绑定固定源码/brief哈希，变化则在派发前拒绝，不能悄悄更换视觉基准。完整brief一并保存在reviewed-rag目录，运行不依赖旧output产物。

设计与代码提示共用工位边界、分阶段夹取/搬运/插入、成员相对位姿、问句标记净空、文字矩形到textAnchor换算及遮挡节拍规则。示例坐标、主题和时长不得直接复制到新选题。这里是生成参考和提示约束，不是对任意生成源码的数学正确性证明；真实模型自动复现能力仍需单独授权并验证。用户认可的是视觉方向，未自动登记工作台验收或整课导出。

设计阶段另由`readReviewedDesignReference`读取`storyboard-reference.json`，包含从样片提炼的工位、状态访问顺序、实测分阶段和标签占位。工作台新设计、保留原稿修订及CLI设计/prepare-design均使用它；数据绑定已认可样片的源码/brief哈希，不执行样片。该JSON是agent整理的规划参考，不是用户另行批准的设计结果。当前任务的口播/cues/Schema仍优先且不变；状态访问列表中的重复idle表示返回同一状态，不是重复定义。修订仍须保留原机制，不能把参考当作无反馈重做或豁免检查的理由。

### 确定性标签布局建议

离线运行`npm run visual:agent -- propose-label-layout design.json new-proposal.json`，输出独立建议及`new-proposal.json.design.json`。仅对已有标签冲突或标签侵入字幕区计算纵向候选，固定x/尺寸，默认12像素净空、最大96像素位移；按稳定ID顺序贪心选择最近安全纵向位置。无解则保留标签与未解决告警，不移动实体、不增加overlaps、不改口播/状态链或覆盖原稿。路径不按填充矩形避让，实际字体、连线和动画仍须渲染检查；这不是全局布局求解器。

建议记录原/新设计哈希及逐项坐标变更，固定`accepted:false`；`layoutPreflight:passed`仅表示静态占位通过。必须审阅后再明确触发代码生成，不能将建议当作原始模型输出或工作台已验收结果。当前只接入离线CLI，没有自动插入后台生成/重试流程。

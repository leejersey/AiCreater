# 自由画面源码：视觉设计输入改造

## 目标与边界

用户确认回到精致教学画面的自动生成目标，采用现有自由场景源码方案。此改造不是继续扩展 RAG 固定机构，也不是更换 Remotion、引入新组件枚举、增加模型请求或修改输出协议。

旧 source 分支本来支持自包含 SVG 的曲线、局部渐变和遮罩，但设计参考长期偏向 RAG 搬运拓扑，编码参考只留下紧凑运动约束。host-components 还被七种简化绘图限制；它适合有限组件流程，不能当作精致自由插画的等价替代。

## 本轮改动

- source 模式设计参考：通过原有 appearance 描述可识别轮廓、内部语义细节、嵌入文字及前后结构；composition 描述构图、材质、绘制顺序、遮挡和文字层级；beats.action 与原状态字段描述每个实测节拍开始、变化及结束时可见的证据。不新增 JSON 字段。
- source 模式编码参考：从已认可的 CustomWallet 和 ReviewedLoop 原文，用 TypeScript AST 提取有限构造片段，包括局部材质 defs、钱包前后袋/缝线/搭扣、差异化纸张内部图案、循环节点内部结构及曲线绘制/求值。不是把整段样片粘贴给模型，也不是可直接运行的组件库。
- 参考同时绑定源码和 brief 的固定哈希；文件变更会在模型请求前拒绝。只读取文本和解析 AST，绝不导入或执行参考 Scene。
- 工作台 source 模式与 visual-agent 的设计/编码/修订提示使用同一参考。每份新 source 任务保存 art-direction.json，注明 automaticQualityVerified=false。host-motion、host-intent、host-components 的原参考不变；默认 source 也不变。
- 网页仅把 source 的名称从“源码生成（兼容）”改为“自由画面源码”。API 值、付费确认、首次最多两次请求、单次修复、实测时间轴、静态护栏和具体源码哈希审批均不变。

## 防止另一种简化

要求具体、可绘制的构造，不是把背景描述写得越长越好，也不是增加无意义齿轮和图标。参考中的钱包、循环和搬运仅适用于对应主题，不能把所有知识点都画成这些装置。细节服务于教学关系；不设 path 数量、装饰数量或“复杂度达到阈值即通过”的伪画质分数。

源码摘录中包含示例坐标、时间、变量和文字，提示明确要求按当前题材重新推导，不得直接照搬；它们不是独立组件。参考通过、编译通过和几何通过都不是视觉验收。

## 验证与剩余工作

离线替身测试覆盖参考原文/哈希/上下文长度、两阶段请求传递、既有 JSON schema、原节拍保留、设计修订、一次修复、兼容分支隔离及入口命名。聚焦84项通过，custom:typecheck通过。全仓 typecheck 仍有原来3处测试错误，未修无关文件。

本轮没有付费模型/TTS请求、没有新场景执行或渲染，没有修改已批准样片、失败 RAG 候选或它们的验收状态。也没有为了发布文字改动重启服务：Node CLI 在下一次明确提交的任务中读取新提示。

尚未验证模型是否能稳定输出更好的场景。下一次真实对照必须使用同一口播和实测节拍，保留未经人工重绘的原始输出；静态检查后取得该新源码的哈希批准，再检查首帧、机制中间态和末帧。模型协议稳定性、实际画质和音画同步都不能由本轮离线测试代替。

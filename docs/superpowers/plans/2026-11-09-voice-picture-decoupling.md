# 画面与配音解耦（2026-11-09）

问题：Agent 把每句话的帧号写死在画面里，画面和那一次配音绑在一起。换音色、调语速、重新配音或重算时间轴，都要重新生成画面（付费）。

做法：画面按「第几句」安排动画，具体帧号由渲染时的配音决定。

| 层 | 改动 |
|---|---|
| 契约 | Scene 收到 `timing = {durationInFrames, cues:[{start,end}]}`，与 `get_timing` 的第 i 句一一对应；skill / 示例 / `get_timing` 都改用 `timing.cues[i]`。审计关键帧经 Remotion `inputProps` 传入，出片按每章当前配音传入 |
| 检查 | `render_stills` 报告不读 `timing` 的画面（high）与写死帧号（`literal-timing`，收尾前须改）；finish 增加两道关卡：`timing`（读 `timing.cues`）与 `retime`（每句 ±30% 的另一套时间轴上重新渲染默认关键帧，不得有 high 问题）。通过的版本记为 `retimable` |
| 数据 | retimable 版本的有效性只看口播文字与句子划分（brief 去掉时长 + 各句文字），与录音无关：重新配音后仍有效、确认保留。整课导出与重渲染一律用章节当前配音；执行器在章节重新配音后自动提交免费重渲染（`retime_stale`）。写死帧号的旧版本行为不变（随录音失效） |
| 网页 | 已配音章节可「重新配音（付费）」，确认里说明画面是否会跟随；画面版本还是旧录音时提示「本章已重新配音…」并显示按新配音重渲染的视频；「重算时间轴」不再让 retimable 版本失效 |

验证：TS 201、后端 201 测试通过（含 retime 关卡、重新配音后版本保留与自动重渲染、导出用当前录音、旧版本随录音失效）。尚需一次付费运行确认 Agent 能稳定写出读 `timing` 并通过 retime 关卡的画面。

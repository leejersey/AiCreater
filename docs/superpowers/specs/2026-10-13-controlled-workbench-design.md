# 受控手动启停设计（待书面确认）

用户已同意推进设计：默认API/网页，已有进程不重复启动；worker/beat单独确认；停机先检查活动任务，不删卷。本文件细化最小版本，本轮不实施或启停原服务。

## 方案取舍

1. 仅保留现有运行手册：零代码，但每次手动核对重复步骤。
2. **推荐前台受控启动器**：`python3 -m services.workbench status|run`，终端Ctrl+C负责正常退出。直接持有本次Popen对象与新进程组，不保存供后续kill的PID，避免旧PID误杀。
3. 后台守护+PID状态文件/独立stop：需要跨会话身份校验、恢复/孤儿治理与更复杂权限，本版不做；更不做开机自启。

## 最小范围与归属

新增一个Python模块和对应标准库unittest，复用python-dotenv/psycopg与现有API、npm网页命令，package.json可加便捷入口；运行手册/TODO同步。只覆盖当前已验收macOS本地环境（需lsof/ps），不冒称Windows/多机支持。无新依赖、数据库迁移、配置选择器或Docker启动逻辑。

`status`只读检查本机127.0.0.1:8000/3000、当前监听PID及命令/工作目录、API/web健康和PG聚合任务状态；只返回角色/归属/健康/任务计数，不打印配置、源文稿或第三方命令原文。PG连接强制只读/短超时，不能调用Store.initialize或ObjectStore.from_env（后者可能建桶）。只从可信本地dotenv读取配置，不source shell，不覆盖现有私有文件。

`run`前置确认依赖/配置和基础服务已就绪，**不执行compose up**。准确识别同项目已有API/web可复用但永远不接管；未知监听、身份无法核实或状态不健康则拒绝，不释放端口/换端口/重启。已有二者均正常时报告无需启动并退出，不创建后台控制器。当前实际API/web仍由原终端管理。

缺失API用当前Python `-m uvicorn services.api.app:app --host 127.0.0.1 --port 8000 --no-proxy-headers`；网页复用当前 `npm run web`（dev，与手册一致），不自动构建、下载或切换生产模式。API先ready才启动web；端口检查只是快照，启动后的真实子进程/健康失败也必须识别。子进程使用同ROOT、受控服务环境、新进程组，日志留本启动终端，不覆盖旧workbench日志/服务JSON。

本版**不提供启动worker/beat的CLI入口**。分别继续走运行手册人工检查排队收费任务并确认；也不停止已有消费者。默认run不调用Celery/beat、供应商、任务提交/重试或render。现有外部worker若运行仍可能消费用户后来提交的任务，API/web启动不能保证整个平台永远零收费。

## 停机与失败

正常Ctrl+C/TERM触发停止检查：PG不可达或queued/running非零则明确拒绝自动停机，留本控制器/子进程运行，要求人工处理任务后再试。idle时仅向本次仍由Popen持有的活子进程组发TERM，不读旧PID、不使用pkill/killall；等待有界，未正常退出报告阻塞，不偷偷KILL或删卷。没有独立跨终端stop命令。

启动阶段无新增消费者；依赖/健康失败也先检查活动任务：idle才回收本次已启动的子进程，忙或DB不可达则保留仍活的owned进程并进入明确阻塞状态，等待人工处理，不假称全部回滚。绝不停止复用的外部进程。不回滚数据库初始化/建桶，因真实API启动沿用已有行为，前置健康不等于API完全无副作用。其他操作者可在检查后提交任务：不承诺原子停写闸门。controller遭SIGKILL/系统断电无法保证清理，孤儿须按手册现场核验；终端生命周期不替代守护进程。

## 验收

- 单测/受控子进程：默认命令无worker/beat；配置不泄露；同项目已有服务零Popen；未知监听/旧PID/身份变化不接管；启动失败只回收owned；忙或DB失败阻止正常退出；idle仅owned进程组TERM；重复Ctrl+C/超时不自动KILL；并发启动/子进程退出不冒认健康。
- 真实当前工作台只执行status以及已有二者无需启动的run路径；容器/表hash/原件/attempt58不变，0收费/0任务。新建与信号回收用隔离dummy HTTP进程/临时环境验证，不停止现有服务、不触碰原3000/8000；完整冷启动生产服务仍需用户另给停写窗口。
- 不重复无关前端构建、不增加自动quota/GC；资源盘点、商用许可、异地备份与人工听检/nums收费验收仍在TODO。

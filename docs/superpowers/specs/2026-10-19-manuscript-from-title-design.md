# 标题生成教学讲稿（新建页审核后建草稿）

用户已确认：当前「新建课程」仅手写讲稿与设计不符；目标为标题可生成或手写讲稿，生成稿须在本页审核后再创建草稿。方案取舍选单页完成（方案1），不建两步向导，不先建空草稿。

## 目标与边界

- 在 `/courses/new`：填课程名称；可选受众/建议时长/要点；同一文本框手写或 AI 生成讲稿；审核编辑后点「确认讲稿并创建草稿」。
- 创建草稿仍走现有 `POST /api/projects`（`title` + `source_text` + `mode=script`），不计费、不派发分镜/配音/渲染。
- 「生成讲稿」按用户选择不弹费用二次确认，直接请求；页上用一句说明可能产生模型费用。
- **用量记账（首版定案）**：创建前尚无 `project_id`，不得虚构挂到 `project_usage` 的记录，也不新建用户账单表。真实模型调用走现有 provider 适配器时保留其既有调用日志；另写一条结构化应用日志（user_id、字符量、成功/失败）。账单级 usage 若需要，另开规格，不混入本轮。
- 可选提示仅用于生成请求与本地暂存，不写入 projects 表。字段上限：`audience`≤80、`duration_hint`≤40、`outline`≤1000（字符），超限 400。
- 本轮不做：分镜自动生成、空项目先创建、费用确认弹窗、旁路对照采用、两步向导、用户级 usage 新表。

与既有契约关系：课程创建后的「讲稿 → 分镜」仍保持原稿不改写；本功能是创建前的**新**能力（标题 → 讲稿），不改变 source-owned storyboard 规则。

## 页面流程

1. 课程名称必填（≤80）。
2. 可选提示区：受众、建议时长、要点，均可空。
3. 教学讲稿大文本框（≤4000）：可手写/粘贴；或点「生成讲稿」。
4. 「生成讲稿」：无标题则禁用；框内已有非空内容时先警告「将替换当前讲稿」，取消则不变，确认后才请求。
5. 生成中禁用生成与创建按钮；失败保留原讲稿并显示错误，可重试。
6. 「确认讲稿并创建草稿」：标题与非空讲稿均可点；成功后清本地暂存并进入 `/courses/{id}`。
7. 本地草稿恢复继续覆盖 title / 可选提示 / source；文案改为可生成或手写，确认后再建草稿。

## 接口与状态

新增 `POST /api/manuscripts/generate`（课程尚未存在，不能挂 project id）：

- 请求：`title` 必填；`audience` / `duration_hint` / `outline` 可选；长度与 Unicode 校验对齐现有 store 习惯。
- 响应：首版同步返回 `{ text }`。模型输出去空白后为空则 502/上游错误语义；**长度 >4000 则 422 拒绝，不静默截断**（前端提示可缩短提示后重试）。模型慢或需队列时再改为 202+job，本设计不强制首版异步。
- 鉴权：与现有课程 API 相同（需登录会话则要求登录）；Host/Origin 限制不变。
- 无标题或非法输入 400；供应商失败不覆盖前端已有文本；不创建 project/job 行。

本页状态：`idle` →（可选）`confirming-overwrite` → `generating` → `ready` | `error`。手写路径可始终停在 idle/ready 直接创建。

## 实现落点

- 前端：`apps/web/app/courses/new/page.tsx`（及必要的 request/本地草稿字段扩展）；不改课程列表语义。
- 后端：`services/api/app.py` 新路由；讲稿生成逻辑放 workflow/providers 旁的小模块，复用现有模型配置，不改 `POST /api/projects` 语义。
- 测试：无标题禁用/覆盖警告取消与确认、失败保留原文、手写创建、生成后编辑再创建的 `source_text`、API 校验与上限；文档更新 README / 新建页说明。

## 验收

1. 标题 + 可选提示 → 生成 → 可改 → 确认创建 → 课程 `source_text` 为确认后文本，无自动 job。
2. 不生成、仅手写 → 同样可创建。
3. 有内容再生成 → 警告；取消不变。
4. 生成失败 → 原文保留。
5. 创建草稿仍不计费；页面不再暗示只能粘贴讲稿。
6. 模型输出 >4000 → 422，文本框不被覆盖。
7. 生成路径不写入 `project_usage`、不新建账单表。

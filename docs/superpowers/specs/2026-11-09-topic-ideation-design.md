# 新建视频：选题发散 → 选方向 → 卡片内大纲 → 文稿（设计）

日期：2026-11-09 · 状态：待审

## 问题

现在「新建视频」只调一次模型：标题（+ 可选受众、时长、要点、风格）→ 整篇文稿。中间没有探索方向的环节，输入「RAG」几乎一定得到一篇「什么是 RAG」。改提示词解决不了，缺的是流程里的一步。

## 决定（已与用户确认）

- 方案 A（漏斗：发散 → 选方向 → 大纲 → 文稿），加上方案 B 的「补充想法 / 追问」。
- 只做单集；**系列课不做，但数据与接口留口子**。
- 大纲**不单独成页**：选中一个方向后，大纲在这张卡片里展开、编辑、追问。

## 交互

仍是一页、左右两栏。右栏「教学文稿」编辑器不变；左栏从「参数表单」变成「构思区」，按三个状态自上而下展开，前一步的内容不消失（可回看、可改了重来）。

### 状态 ①：输入选题

```
┌ 构思 ─────────────────────────────────────────┐
│ 选题 *  [ RAG                                ] │
│ 补充想法（可选）                                │
│ [ 想讲给做客服系统的同事，别太学术            ] │
│ 风格  (通俗科普) (知识干货)                     │
│ ▸ 更多设置：受众 · 时长 · 画面主题 · 文稿格式     │
│                                               │
│ [ ✨ 发散几个方向 ]      跳过，直接生成文稿 →    │
└───────────────────────────────────────────────┘
```

- 「选题」取代原「课程名称」作为输入；课程名称在选定方向后自动填成该方向的标题（可改），创建前仍可编辑。
- 「补充想法」是方案 B 的入口：一句话说明意图、对象、想避开什么。
- 受众、时长、主题、格式收进「更多设置」，默认折叠（已有值时显示摘要，如「受众：开发者 · 3 分钟」）。
- 「跳过，直接生成文稿」保留现在的一步生成，给已经想清楚的人。

### 状态 ②：方向卡片

```
│ 4 个方向  · 换一批 · 我自己说一个               │
│ ┌──────────────────────────────────────────┐ │
│ │ ☐ 为什么大模型会一本正经地胡说？            │ │
│ │   问题驱动 · 入门 · 约 3 分钟 · 4 章         │ │
│ │   开场：「你问它昨天的新闻，它答得头头是道…」  │ │
│ │   看完能：说清 RAG 解决什么问题              │ │
│ │   章节：幻觉从哪来 / 外挂知识库 / … / …      │ │
│ │                          [ 用这个方向 ]     │ │
│ └──────────────────────────────────────────┘ │
│ ┌ ☐ 跟着一个问题走完 RAG  旅程 · 入门 … ─────┐ │
│ ┌ ☐ 做 RAG 时最常踩的 5 个坑  误区 · 进阶 … ──┐ │
│ ┌ ☐ 从关键词搜索到向量检索  演进 · 进阶 … ────┐ │
│ 已勾选 2 个 → [ 合并成一个方向 ]                 │
```

- 一次 4 个方向（可配 3–6）。卡片紧凑时只显示标题与标签，悬停或展开看开场、收获、章节标题。
- **换一批**：再要一批，把已出现的方向发给模型要求避开。旧的一批折叠保留，可以翻回去。
- **我自己说一个**：在卡片列表下输入一句方向描述，模型把它整理成同样格式的卡片。
- **合并**：勾 2 个 → 生成一张融合卡（如「问题驱动的开场 + 踩坑清单的主体」），原卡保留。
- 发散保证（写进提示词并在后端校验）：
  - 每张卡的「结构类型」互不相同，取自：问题驱动、旅程 / 流程、对比、误区纠正、实操、演进 / 历史、故事；
  - 至少覆盖两个深度（入门 / 进阶 / 深入）；
  - 若用户写了受众或补充想法，所有卡片都要服从它，只在角度上发散；
  - 不编造数据、产品名与出处（与文稿生成同一规则）。

### 状态 ③：选中卡片 → 卡片内大纲

点「用这个方向」，其他卡片收起为一行，这张卡片原地展开为大纲：

```
│ ▾ 为什么大模型会一本正经地胡说？  问题驱动·入门    │
│   课程名称 [ 为什么大模型会一本正经地胡说？     ]  │
│   ┌ 1 幻觉从哪来                       ≈40 秒 ┐ │
│   │ · 模型只记得训练时见过的东西                │ │
│   │ · 问到新知识时会「编」                     │ │
│   │ 画面：一个答题的模型，答案被划掉             │ │
│   └──────────────────────────── ↑ ↓ ✎ ✕ ──┘ │
│   ┌ 2 给它一本可以翻的书 …                     ┐ │
│   + 加一章                                     │
│                                               │
│   追问 / 调整：[ 第 3 章换成客服场景的例子      ]  │
│   [ 按意见调整大纲 ]   ↶ 上一版                  │
│                                               │
│   [ ✨ 按这个大纲生成文稿 → ]                    │
```

- 大纲每章：标题、1–4 个要点、**画面构想**（一个会变化的物体或过程，而不是「展示一张卡片」）、预计秒数。
- 直接编辑：改字、上下移动、删除、加一章（纯前端，不调用模型）。
- **追问 / 调整**（方案 B）：一句意见 → 模型改大纲（只改提到的地方），保留历史可「上一版」。
- 预计时长合计超出「时长」设置时提示；单章超过 110 秒提示拆分（与工作台规则一致：Agent 只生成 120 秒以内的章节）。
- **按这个大纲生成文稿**：调用文稿生成，右栏填入结果（已有内容时沿用现在的「替换现有讲稿？」确认）。Markdown 格式下每段对应一章：标题 = 章节标题，画面意图以「画面构想」为基础。

右栏不变：生成后可继续编辑，「创建草稿」按钮与现在一致。

## 数据与接口

### 接口（均为短调用、计费；使用账号自己的模型或服务端 DeepSeek，与文稿生成同一套 `resolve_llm`）

| 接口 | 输入 | 输出 |
|---|---|---|
| `POST /api/ideas/angles` | `topic, notes?, audience?, duration_hint?, teaching_style, count(3–6), exclude?: 标题[], custom?: 一句方向, merge?: [angle, angle]` | `{angles: Angle[]}` |
| `POST /api/ideas/outline` | `topic, notes?, angle, audience?, duration_hint?, teaching_style, previous?: Outline, feedback?` | `{outline: Outline}` |
| `POST /api/manuscripts/generate`（扩展） | 原字段 + `plan?: {angle, outline}` | 不变 |

`custom` 与 `merge` 复用 angles 接口，返回 1 张卡。

```
Angle   = {title, hook, audience, takeaway,
           structure: problem|journey|compare|myth|howto|history|story,
           depth: intro|intermediate|advanced,
           duration_min, chapters: string[3..8],
           scope: 'single'}                      // 系列课口子，见下
Outline = {sections: [{title, points: string[1..4], picture, seconds}] (1..20)}
```

- 后端校验：JSON 结构、字段长度、`structure` 互不相同（angles 批量时）、章节数、秒数合计；不合格时重试一次，再不合格返回错误，不把半成品交给前端。
- 模型输出用 `response_format: json_object`；DeepSeek 关闭思考（与现在文稿生成相同）。

### 保存

- 构思状态（选题、补充想法、各批卡片、选中卡片、大纲及历史）存在现有本机草稿（`useLocalDraft`），刷新不丢。
- 创建课程时把来源写进 `projects.config.origin`：`{topic, notes, angle, outline, scope:'single', series_id:null}`。
  - 之后工作台、Agent 分镜稿可以引用：给 Agent 的 brief 增加「本课方向」一行（结构类型 + 看完能得到什么），让画面贴合方向。
  - 不影响旧课程（没有 origin 就照旧）。

### 系列课的口子（这次不实现）

- `Angle.scope` 现在只允许 `'single'`；以后增加 `'series'`，卡片带 `episodes: Angle[]`。
- `origin.series_id` 现在恒为 `null`；以后系列课是一条 series 记录，每集一个 project 指向它。
- `/api/ideas/angles` 以后加 `scope` 参数即可生成系列方向；前端卡片组件按 `scope` 渲染。现在 API 收到 `scope≠'single'` 返回 422。

## 费用

- 发散一批约 1 次短调用（输出约 1–2k token），大纲一次约 1k，追问一次约 1k，文稿与现在相同。
- 页面在每个按钮上标「AI 生成计费」；配了 `DEEPSEEK_PRICE_*` 时显示估价，否则只显示「计费」，不编造价格（与 `costs.py` 规则一致）。用账号自己模型时费用由其服务商收取。

## 不做

- 系列课；对话式多轮聊天窗口（追问只针对当前卡片 / 大纲，一次一句）；联网检索资料。

## 测试

- 后端：用假的模型客户端测 angles / outline 的校验（结构类型重复、字段超长、秒数超限、非 JSON → 重试一次后报错）、exclude / custom / merge、`scope≠single` 拒绝、`origin` 写入与旧课程兼容、plan 传入文稿生成时进入提示词。
- 前端：状态 ①→②→③ 的单元测试（换一批保留旧批、合并需恰好 2 张、大纲编辑与上一版、超时长提示、跳过直达）。
- 浏览器：测试账号走一遍完整流程。真实模型调用（发散、大纲、追问、文稿各一次，约几分钱）需要你回复「开始」后才跑。

## 开发顺序

1. 后端 `services/workflow/ideation.py` + 两个接口 + 文稿生成接收 `plan` + `origin` 保存（含测试）。
2. 前端构思区三状态 + 本机草稿保存（含测试）。
3. Agent brief 引用「本课方向」。
4. 浏览器验证（免费部分）；付费验证等「开始」。
5. README、CHANGELOG。

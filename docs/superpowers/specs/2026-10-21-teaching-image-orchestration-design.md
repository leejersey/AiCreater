# 教学图片编排设计（首版）

状态：依据用户已认可的方向编写；待用户审阅本文后进入实施计划。本文不是已实现功能说明。

## 1. 目标与验收原则

图片是教学对象，不是背景装饰。AI 导演判断何时图片比文字、代码、图形更能降低理解成本，并决定对象、构图、与现有元素的关系、口播锚点与动作。

基本原则：
- 不需要图片是合法且常见的判断；不能为了用模型而生图。
- 概念类比、对象外观、空间关系可用生成图；命令、公式、数据及精确结构由组件渲染。
- 软件真实界面、执行结果与实验记录不使用生成图片冒充证据。
- 一个需要独立入场或强调的对象对应一个独立素材，不假定能从合成图里可靠分割对象。
- 首版是否成功，以图片是否帮助理解、是否正确配合口播为准，不以生成张数或装饰程度为准。

示例：解释“两个项目的依赖互不影响”，可生成两个工具箱素材；项目名、版本文字、边界与箭头由组件绘制。两个工具箱随对应口播入场，说到“互不影响”时聚焦其边界。真实命令仍由代码组件展示。

## 2. 范围与方案选择

方案 A：生成完整教学海报。实现较快，但文字难改、对象不能独立动作，不采用。

方案 B（采用）：AI 生成素材需求；模型提供对象图；渲染器负责文字、排版和时序。需要扩展资产和分镜协议，但能复用当前编辑、配音对齐与导出。

方案 C：自动分层、分割对象与任意角色动画。可控性、费用和实现复杂度过高，暂不做。

首版限制：
- 每场景 0–2 个图片需求；每需求每次生成 1 个候选，不默认生成多张供挑选。
- 首版先支持 card_sequence、comparison_panel、code_walkthrough 的图片组合版式；其他场景使用原有图形。AI 必须知道这个限制，不能生成无法渲染的需求。
- 组合版式预留图片区与代码/文字区，不能把图片直接覆盖在现有满屏模板上。每张图等比完整显示，不自动裁掉主体，避开标题与字幕。
- 支持出现、聚焦、高亮：出现复用元素入场；高亮/聚焦复用现有强调逻辑及受限图片容器效果。不新增任意坐标动画语言。
- 不做自动网页截图、录屏/GIF、任意物体分割、生成式视频、人物口型或多轮图片编辑。
- 本阶段以生成图片为来源；素材底座保留静态图片扩展能力，但手动上传 UI 不与首版一起铺开。

## 3. 数据与职责

### 3.1 AI 导演输出

扩展现有分镜生成，而不是额外自动发起一次规划模型调用。每场景输出图片决策（需要/不需要及简短教学理由）。需要时给出 1–2 个需求：
- 稳定需求 ID、教学目的、图片对应的教学对象；
- 主体描述、构图与负面约束；
- 所属图片槽及关联元素 ID；
- 原文引用锚点、出现和强调意图；
- 共用课程风格，不把标签、命令和精确数字写进图片；
- 人工可读的提示词草案，最终提示词由系统合并课程风格与安全区约束。

ID、槽位、引用长度、字符串长度、每场景图片数量均受限。禁止模型输出文件路径、远程素材 URL、API 参数、可执行命令或任意 CSS/脚本。

### 3.2 三类数据分离

1. 图片计划：未生成的需求、教学理由、提示词、候选状态。属于工作台/任务元数据，不作为已存在图片放进最终视频 DSL。
2. 图片资产：下载并校验后的不可变 PNG/JPEG，以及尺寸、内容校验值。存储复用私有对象存储与本地渲染缓存。
3. 场景绑定：已接受的资产、槽位、关联元素和口播锚点。只有已解析、可访问且校验通过的绑定进入最终视频 DSL。

生图溯源（模型、提示词、参数、风格快照、时间、任务 ID）保存在项目/版本元数据；视频 DSL 只携带渲染所需字段，不包含凭据和提供方临时链接。

原始 Markdown 继续作为文稿存档，不用图片二进制、base64 或临时 URL 污染口播字段。课程风格由现有主题/视觉风格派生，作为生成任务快照保存，首版不新增复杂风格库。

### 3.3 Schema 与现有组件

以 packages/video-schema/schema.json 为源更新 TS 类型及 Python/TS 双端验证，不直接编辑生成的 types.ts。

资产从仅音频扩展为严格区分 audio/image 的结构。音频仍须 duration_ms；图片须有可校验的格式与宽高，禁止将图片用于 narration.audio_asset_id。资产数量上限应兼容最多20场景的音频与每场景两图，而不是放开无限资产。

最终绑定不得悬空、跨项目或引用音频。验证器须保证图片槽、关联元素与动作目标存在，图片锚点仍来自当前场景口播。既有无图项目保持验证与渲染兼容。

图片组合版式使用共享的图片/标注层，但不得绕过 CodeLesson、专用演示模板的现有渲染分支。明确分流支持的场景，未支持组合应拒绝而不是静默漏图。每个可独立强调的图片槽关联一个独立的已有教学元素，复用该元素的 ID、入场与强调锚点；两张独立运动图片不能共用同一个动作目标。先通过固定版式满足关系表达，不开放任意像素坐标。

所有提取/清理场景字段的路径（分镜恢复、Jobs._draft_scene、生成/重生成、配音/对齐配置、候选接受、前端预览及版本导出）须显式处理图片绑定与资产，不能因旧白名单而漏图，不能把计划元数据误当最终 DSL。

## 4. 用户与任务流程

1. AI 生成文稿和分镜，展示图片决策、用途、对应口播、提示词及预计张数。
2. 用户编辑计划或选择不用图；不因看到计划就自动付费生成。
3. 用户勾选需求，查看费用信息并确认后提交独立 image_generate 任务。
4. 任务冻结模型、参数、提示词、风格、课程/场景修订、需求 ID 与授权数量；每需求一次请求、一个候选。
5. 完成后展示候选及使用目的；用户选择接受或放弃。重新生成是新的显式收费操作，不自动覆盖已接受图片。
6. 接受图片后，与已有代码、标签、箭头一起预览，再按原有流程配音、对齐和导出。已有配音无需重做。

任务复用 PostgreSQL 的可靠状态、现有 Celery 唤醒及受控子进程，不新建队列框架。需完整更新 jobs SQL 约束、API 校验/权限、worker 分支、错误映射、重试、估算、用量记录及公开任务返回字段。

API 必须验证项目归属、场景/需求修订与确认字段。任务 hash 包含冻结需求和模型参数。重复提交复用同一任务；显式重新生成使用独立请求身份，不能因幂等缓存一直返回被放弃的图片。

## 5. 时序、编辑与版本

图片的出现和强调先绑定原文引用，再由真实配音时间戳确定帧数。不让 AI 编造秒数，也不修改口播来适应图片。

换图但不改口播：保留音频和时间戳；只失效相关视觉预览/渲染。改变锚点：重新校验并使用现有对齐缓存，不默认收费重配音。

口播变化：失效受影响的图片锚点，提示复核，不默默把旧图绑定到新句子。分镜重生成：保留已生成候选及旧绑定记录，供显式复用；不静默丢图，也不自动应用到语义已变化的场景。

图片任务完成时若场景/需求已改变，保存为旧修订候选，不能覆盖新场景。取消任务后迟到结果也不能自动绑定。

保存版本时冻结所选资产、绑定、图片计划与生成溯源。重生或换图不改变旧版 MP4、旧版本预览或素材引用。图片资产不可原地覆盖，不在本阶段增加自动清理。

## 6. 提供方、安全与费用

目标模型为 gpt-image-2。首个真实接入前核对当前官方文档、账号可用性、端点、参数与价格；未经核对的功能或单张价格不写死。使用现有 HTTP 客户端；不为一次调用新增代理框架。

凭据仅在后端读取，不存入任务、日志、项目、DSL、前端或生图提示词。现有校验器/渲染器子进程的环境过滤同时补齐生图密钥，只有实际生图工作进程可以读取所需凭据。模型响应按大小限制读取，图片必须解码验证、限制文件大小与总像素，拒绝伪装格式、动画和解码炸弹；图片统一经过安全编码后存入私有资产库。公开资产读取继续验证项目归属，不暴露静态公共链接。

优先使用提供方直接返回的图片数据。若实际接口只提供下载 URL，必须额外约束域名、HTTPS、重定向、目标地址、响应大小与超时；不接受模型自行指定下载地址。

首版不保证透明背景；通过独立对象图、简洁底色和容器融合排版，不能承诺可靠抠图或像素级主体位置。提示词要求不是质量保证，候选仍需预览和人工接受。

付费边界：
- 每需求每次一个候选；张数、模型及已知费用信息在确认前可见。
- 未核对价格显示“费用未知”，不得伪装成精确估价或保证上限。
- 已有相同需求且被接受的资产优先复用，复用不收费。
- 提供方拒绝、超时、取消、网络中断不自动再次提交。可能已收费但未收到结果时标记结果不确定，要求用户确认后才能产生新的付费请求。
- 现有通用 retry 端点与 worker 自动恢复不能绕过生图确认；子进程崩溃后不推断请求从未发出。
- 现有文稿、分镜、TTS 授权不涵盖生图。本文获批也仅授权开发与离线测试，不授权真实生图消费。

## 7. 测试与验收

先写失败测试再实施，所有默认测试使用假提供方，不访问收费接口。

核心场景：
1. 纯代码教程判断不需要图片，无图片请求；旧项目无图预览/导出不变。
2. 概念教程生成1–2个合理需求；独立素材能随口播分别出现、聚焦，与文字/代码共同显示。
3. 命令、字幕、公式及关键标签由程序渲染，生图提示词和素材说明不进入TTS。
4. TS/Python 同时拒绝超量需求、无效槽位、悬空引用、非口播锚点和不支持组合。
5. 超大/损坏/伪装图片被拒绝；图片和音频不能混用；对象存储、本地校验和跨账号隔离有效。
6. 双击提交只调用一次；请求超时、重启、取消、显式重试均不能隐式二次计费。
7. 编辑中的迟到结果只保存候选，不覆盖新修订；换图不重做TTS，旧版本保留原图。
8. 预览与导出素材一致、无文字/字幕遮挡；前端提供任务状态、失败原因、接受和放弃入口。

离线完成后，再单独申请小样预算：用同一段口播比较纯图形与图片融合版，检查是否更容易理解、主体是否可辨、风格和留白是否可控。不承诺未经实测的质量提升或生成费用。

## 8. 推荐实施顺序

1. 图片资产与绑定契约、私有存储、校验、冻结版本及假图片渲染闭环。
2. AI 导演图片决策与需求、受限组合版式、口播锚点动作；离线测例证明不是背景贴图。
3. 独立生图任务、GPT Image 2 提供方、确认/用量/幂等/超时安全。
4. 工作台候选预览、接受/放弃、换图与重生成保护，浏览器及全量回归。
5. 另行授权真实小样验收。

当前未实现这些能力，未提交真实生图请求。仍待实施时核对的外部事项：提供方实际访问权限、API参数、报价及输出格式；这不影响先完成无费用的资产与编排测试。

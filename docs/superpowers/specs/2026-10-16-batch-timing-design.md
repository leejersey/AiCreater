# 整课批量本地对齐

**状态：** 用户已确认设计；代码与隔离验收完成，原API尚未受控加载。580项去重测试、typecheck、私有构建和10项受控页面检查通过，见[验收](../../../output/workbench/batch-timing-qa/receipt.json)。只做显式批量登记/复用本地timing任务，不启动消费者、不处理旧队列，也不调用模型或配音。

## 目标与方案

多章手工调整cue后，在整课总览选择已保存、已人工核对的待对齐章节，一次确认提交。复用单章缓存对齐、持久任务与旧结果发布护栏，不建新调度器。

- **采用后端事务批量提交**：同一项目锁内校验整组选项与缓存，再登记任务；有一章失败则本次整笔回滚，不留半批新任务。
- **不采用前端逐章循环**：虽然少一个接口，但中途409/缓存缺失会留下部分已提交任务，不能兑现整批提交语义。
- 不做自动扫描/全选所有章节后直接运行、重新配音、任务自动重试或跨章执行回滚。

## API与事务

新增`POST /api/projects/{project_id}/timing`，返回202及现有公开Job数组。请求沿用批量配音结构：项目`expected_revision`、`confirmed:true`、1–20项`scenes:[{scene_id,expected_revision}]`；严格拒绝额外字段、重复ID、布尔/非整数revision或未确认提交。

1. `Jobs.submit_batch_timing`在现有连接事务内锁项目，检查项目revision、活动场景归属、逐章revision和`needs_timing`。批量不接受ready/needs_voice/已归档章；单章原来支持ready或needs_timing的规则不改。
2. 从`Jobs.submit_timing`提取最小共享payload构造逻辑，不从批量方法循环调用会另开事务的单章入口。为每章检查原音频资产及本地缓存，冻结相同的教学稿、资产、words_checksum、config、有效profile和`local-timing:1`协议。
3. 全组选项和payload准备成功后，用同一事务内的`_submit`登记。继续以完整`input_hash`去重，单章/批量/并发重复提交相同输入得到同一任务；任意事务内插入或任务读取失败也回滚本次新行。既有任务不删除、不取消、不改attempt。
4. 现有项目→任务锁顺序不变；提交不改scene/project revision、正文、人工核对、音轨、字幕、动画、版本或候选。只产生或复用普通timing jobs，attempt仍由后续显式执行器领取。

项目/章节冲突或状态不合适409、归属/重复/请求/缓存校验422、Host/Origin403，复用当前错误协议且不泄露本地路径或供应商信息。缺缓存错误不触发下载、ASR或配音兜底。

## 缓存、复用与执行边界

提交沿用现有`cache_snapshot`的文件边界、大小、非空和音频checksum检查；不新增缓存下载或词戳修补。它不是完整JSON/词戳/语义检查：缓存内容无法解析、字词无法匹配或时长不符仍可能在执行阶段失败。冻结后缓存被改，worker须按原逻辑失败而非使用新数据。

- 通过本次revision/状态/缓存校验后，相同payload已有queued/running/succeeded/failed/cancelled任务均原样返回；不得借批量入口把失败任务重置或隐式重试。用户到持久任务/单章入口检查并按既有规则显式处理。
- revision、profile、教学稿、资产或words checksum不同，不冒充相同输入；服务端去重为准，不按前端最近50条列表推断“没有历史任务”。本次不扩展历史列表/新增当前timing任务投影或计数。
- **原子性仅限提交事务**。运行后每章独立成功/失败/取消，不能承诺整课同时ready，也不撤销已成功章节。
- 复用现有`publish_voice`的revision/profile/attempt护栏与冻结资产一致性检查。编辑、换音色或重试后，旧结果不能覆盖新稿；旧版本与媒体不动。

## 最小界面

在`CourseOverview`沿用现有章节核对区，为needs_timing章增加独立选择框和“选择已确认待对齐章节”“批量本地对齐（N章）”。配音选择与对齐选择分开，均按场景ID+revision绑定；未保存、忙碌、未核对或无音频引用时不能提交，不自动代勾人工核对。

一次普通确认明确：替换所选章字幕与入场时间、保留音频、不调用模型/配音、匹配任务复用而失败不自动重试。取消零POST；成功只合并返回任务并展示“登记或复用，执行进度见持久任务”。不自动刷新覆盖输入、预览、导出、启动消费者或跳转。

400/409/422/网络失败保留选择与所有现有草稿；不自动重发。响应不明时不冒称零任务或成功，可手动查看持久任务后再次明确提交，后端同输入去重。切课/退出后的晚响应不能写入新课程；旧API404显示未启用，不回退逐章提交。核对或revision变化后旧选择失效，不把排队当成完成。

消费者检测继续仅提示；不因本功能变成自动启停或执行授权。页面沿用现有组件/样式/可访问label，不做布局重设计。

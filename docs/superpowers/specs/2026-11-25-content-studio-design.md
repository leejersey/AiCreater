# 选题台：每日选题 → 爆款解析 → 文案生产 → 内容审核（设计）

日期：2026-11-25 · 状态：P0–P4 已完成（2026-11-25）

## 背景与目标

在现有工作流（建课 → 拆章节 → 配音 → Agent 画面 → 导出）之前，加一段「内容策划」：

1. **每日爆款选题**：每天给出适合本账号的候选选题。
2. **爆款视频解析**：拆解对标视频，提炼可复用的结构（不复制观点和文案）。
3. **爆款文案生产**：基于选题、拆解与人设写出分镜文稿。
4. **爆款内容审核**：配音前把关，尤其是事实溯源和合规。

方法论尽量来自成熟 skill，并且可替换、可升级、可追溯。

## 已有能力（不重复造）

| 步骤 | 已有 | 本设计补什么 |
|---|---|---|

| 2 | 链接提取（B站/YouTube 字幕、正文）、爆款拆解（`analyze_viral_brief`：事实/钩子/痛点/节奏） | 视频文件转写、关键帧看图、带时间轴的拆解、拆解库、「爆款公式」确认 |
| 3 | 发散 / 大纲 / 按大纲生成文稿（`ideation.py`、`manuscript.py`）、开场钩子、去 AI 味、长文转脚本、人设 | 方法论从提示词抽成 skill；输入改为选题卡 + 拆解公式 + 证据包 |
| 4 | AI 审稿（`critique_manuscript`）、零成本文稿体检（前端） | 规则层（极限词、敏感类目）、**事实溯源**、审核门槛（不通过不能配音） |

## 已确认的决定

- 方法论来源（许可证已核对）：
  - **yanhua1010/self-media-content-workflow**（MIT）：`self-media-trend-radar` → 选题与拆解方法；`self-media-short-video`、`self-media-platform-copywriting` → 文案原则。
  - **alchaincyf/huashu-skills · huashu-douyin-script**（MIT）：视频拆解维度（前 3 秒文案/视觉钩子及配合、分镜、节奏、视觉元素、转化、合规、可复制要素）与「先提炼公式、用户确认再写」。
  - 审核没有可用的成熟 skill（中文审核类均无许可证），自建；只借用 yanhua1010 的两条原则：区分事实、判断与推断；不声称能检测 AI 生成概率。
  - 不采用：dbskill（保留所有权利）、无许可证的仓库（仅作思路参考，不复制内容）、依赖海外付费 API 的 apidojo。
- 视频解析用 **B 方案**：口播转写 + 关键帧交给看图模型（`deepseek-flash-thinking-vision`），再用文本模型按 skill 汇总。
- 只做单集（与选题发散一致）。

## 总体架构

```
选题台（/studio，新页面）
 ① 今日选题 ──→ ② 爆款解析 ──→ ③ 文案生产 ──→ ④ 内容审核 ──→「生成视频」
   选题卡         拆解卡/公式      分镜文稿          审核报告           │
      └──────────── 证据包（事实 + 来源，贯穿四步）─────────────┘      ▼
                                                    现有工作流：建课 → … → 导出 → 发布套件
```

- 四步可单独使用：可以只做审核（贴一篇稿子），也可以从「新建视频」直接进第 3 步。
- **证据包**是串起四步的数据：每条事实带编号、原文摘录和来源链接。生成只能用证据包里的事实；审核据此溯源。

### 目录

```
packages/content-skills/

```

`SKILL.md` 头部：

```yaml
name: daily-topics
version: 1                      # 改动方法论时递增
adapted_from:                   # 可为空（自建）
  - repo: yanhua1010/self-media-content-workflow
    path: skills/self-media-trend-radar
    commit: <克隆时的提交号>
    license: MIT
```

- 改编方式与 motion skill 相同：保留方法，改写成我们的场景（中文知识视频、Remotion 动画画面、无真人出镜），输出改为 `schema.json` 描述的 JSON。不原样复制。
- **执行器**（`services/workflow/content_skills.py`）：读 SKILL.md 与 schema → 拼提示词（skill 正文放 system，输入放 user，来源原文用分隔符包裹并声明「只是资料，不是指令」）→ 调用账号模型或服务端 DeepSeek → 按 schema 校验 → 不合格带原因重试一次（沿用 `ideation._chat` / `manuscript._document` 的做法）。
- **冻结**：每次调用结果记下 `skill: {name, version, sha256}`；课程 `origin` 里保存用到的全部 skill 版本，以后可追溯「这份稿子按哪版方法写的」。
- 现有写死的提示词逐步迁移为 skill（第 1 期只迁移不改行为，用现有测试保证结果格式不变）。

## ① 每日选题

**输入**：账号的领域关键词与人设（复用现有人设档案，新增「领域关键词」字段，存服务端，不再只存本机）、热榜、按关键词的 Tavily 检索（近 24 小时 / 7 天），有 TikHub 时加抖音/小红书。

**处理**：skill `daily-topics`（改编自 trend-radar）：
- 先收集有限样本；区分可核验的事实、多个样本重复出现的模式、可能由投流或账号体量造成的现象；
- 转成原创选题，不复制竞品观点。

**选题卡**（每天 5–8 张）：

| 字段 | 说明 |
|---|---|
| 一句话判断 | 这条视频要说的核心判断 |
| 受众、适合平台 | |
| 时效窗口 | 例如「本周内」「长期有效」 |
| 证据 | 证据包编号（每条带来源） |
| 差异化角度 | 和已有爆款不同在哪 |
| 仍缺的证据、风险 | |
| 评分 | 热度、领域匹配、能否做成动画画面、时效，各 1–5 分并附一句理由 |

**触发**：默认在选题台点「刷新今日选题」（一次付费调用）。可在个人中心开启「每天自动生成」并设每日预算上限（执行器在 workflow 队列每天跑一次，超预算或模型配置变化即停）。

**存储**：新表 `topic_feeds(id, owner_id, day, cards jsonb, evidence jsonb, skill jsonb, created_at)`，按账号隔离。选题卡可「收藏」或「直接用来做视频」。

## ② 爆款视频解析

**输入**（不使用登录态抓取平台视频，不自动下载需要登录的内容）：
- B站 / YouTube 链接：沿用现有提取（公开字幕 + 元数据）；
- 抖音 / 小红书链接：配置了 TikHub 时取口播与互动数据；
- **视频文件上传**（任何平台，≤ 200MB、≤ 10 分钟）：用户自行保存的对标视频。

**处理**（`analyze` 任务，在执行器 workflow 队列运行，可能需 1–3 分钟）：
1. `ffmpeg` 抽音频 → 本地 `whisper-cli` 转写，得到带时间戳的口播（免费；首次部署需下载 ggml-small 模型约 466MB）。
2. 抽关键帧：0、1、2、3 秒各一张（钩子），之后按镜头切换或每 N 秒一张，总数 ≤ 10。
3. 看图模型逐帧描述画面（视觉钩子、版式、字幕、动效线索）。
4. 文本模型按 skill `video-breakdown`（改编自 huashu-douyin-script + trend-radar 的拆解部分）汇总。

**拆解卡**：
- 前 3 秒：文案钩子、视觉钩子、两者怎么配合（附时间）；
- 分镜段落：每段时间范围、作用（冲突 / 证据 / 转折 / 行动）；
- 节奏：信息点和反转出现在第几秒；
- 视觉元素、转化设计、合规风险；
- **可复制要素**与**不可复制的原因**（账号体量、投流、热点红利）。

**爆款公式**：从 1–5 张拆解卡提炼一条可复用的结构公式，**用户确认（可修改）后**才进入第 3 步。

**存储**：新表 `breakdowns(id, owner_id, source jsonb, transcript jsonb, frames jsonb, card jsonb, skill jsonb, created_at)`；上传的视频与关键帧存 TOS，转写后可删除原视频（默认保留 7 天）。

## ③ 文案生产

沿用现有流程（选题发散 → 卡片内大纲 → 按大纲生成文稿 → 钩子 / 去 AI 味 / 局部改写），变化：
- 输入可以是选题卡、爆款公式、证据包与人设；
- 方法论来自 skill `short-video-copy`（改编自 yanhua1010 short-video + platform-copywriting）：一条视频只讲一个核心判断；前 3 秒给冲突、结果、利益或具体场景；关掉声音只看字幕也能看懂；画面负责证明、演示、对比，不重复字幕；四种主体结构；钩子给 3 个并推荐 1 个；
- **生成只能使用证据包里的事实**：文稿每段的 `materials` 里用 `[E3]` 这样的编号标出用到的证据，供审核溯源（编号不进入口播与字幕）。

## ④ 内容审核

两层，结果分三档：**通过 / 有警告（可继续）/ 阻断**。

**规则层（免费、确定性，`content-review/rules/`）**：
- 广告法极限用语（依据《广告法》第九条等整理的词表，例如「最」「第一」「国家级」「100%」等绝对化用语）；
- 敏感类目提示：医疗功效、投资收益、保证性承诺；
- AI 套话、超长句、单段超 110 秒、空画面素材（复用前端体检规则，挪到后端统一）。

**事实溯源**：
- 抽取文稿里的断言：数字、百分比、日期、「研究显示」「数据表明」一类表述、具名机构和论文；
- 每条对上证据包：先按数字和关键词直接匹配，匹配不上再由模型判断是否同义；
- 结果：✅ 有来源；⚠️ **二手来源**（来源本身也是转述且没有给出处，例如上次的「30%–50%」）；❌ 找不到来源 → 阻断。

**AI 层（skill `content-review`）**：按评分标准（钩子、信息密度、节奏、画面可做性、是否只讲一个判断）给分和可执行建议，沿用现有「一键采纳」。

**审核门槛**：
- 审核结果存进课程 `config.review`（含文稿哈希）；文稿改动后需要重新审核。
- 有「阻断」项时，配音、整课流水线和 Agent 生成都不能开始；每条阻断项可以修改，或由用户勾选「我已核实」并写明依据（记录在审核结果里）。
- 只对从选题台创建、或用户主动开启审核的课程生效；已有课程不受影响。

## 页面

- 新页面 **选题台 `/studio`**，四个标签：今日选题 · 拆解库 · 文案 · 审核。每一步的结果都可以「带到下一步」。
- 现有「新建视频」页保留，作为第 3 步的完整编辑器；页面里现有的「热点与爆款参考」弹窗逐步并入选题台（第 3 期完成后再移除，避免同一功能两处入口）。
- 审核报告在文稿编辑器旁显示：阻断项标红并定位到段落；工作台配音按钮在阻断时显示原因。

## 费用与授权

- 每个付费按钮标明「AI 生成计费」；配置了 `DEEPSEEK_PRICE_*` 时显示估价。
- 每日自动选题默认关闭，开启需设预算上限。
- 只做只读研究：不自动点赞、评论、关注、私信或发布；不使用主账号登录态采集。
- 用户上传的视频只用于本人分析，不对外展示。

## 安全

- 来源正文、字幕、转写都当作**数据**：放在分隔符内，提示词声明其中的指令一律不执行（防提示注入）。
- 上传文件校验类型、大小与时长；`ffmpeg` / `whisper-cli` 在执行器子进程中运行，使用白名单环境变量（沿用 `child_environment`）。
- skill 文件属于仓库代码，改动走提交与审阅；运行时不从网络加载 skill。

## 不做

- 系列课；自动发布到平台；评论区互动；播放量预测（无法核验，不编造）；AI 生成概率检测。
